# Session Query Catalog

One line per named query: its purpose, plus any param beyond the scope params every query takes (`after_date`, `before_date`, `project`, `host`). The full description, caveats, defaults, and examples are in the YAML header at the top of `resources/queries/<name>.sql`; read it before running a query you have not used. The tables, views, and macros the [`SKILL.md`](../SKILL.md) name index points to follow.

The query lines are generated from those headers. Edit the header, then regenerate with `UPDATE_QUERY_CATALOG=1 bun test plugins/observability/skills/session`.

## Named Queries

- `activity`: Session interaction profile: one row per prompt source, plus interruptions, queued goals, scheduled fires, compactions, API retries, hook friction, and the distribution of permission modes.
- `already-allowed-still-prompting` [`allow_glob`]: Bash permission prompts whose command matches a `permissions.allow` pattern you pass as `allow_glob`.
- `bare-refs` [`per`]: How often main-thread assistant prose cites a PR, issue, or ticket as a bare ID (`#N`, `repo#N`, `!N`, `ENG-123`) instead of a markdown link or URL.
- `catalog-reinjection-thrash-sessions` [`min_injections`]: Sessions re-injecting the full skill catalog and deferred-tools delta, cumulatively re-billing the same context.
- `classifier`: Auto-mode classifier volume and latency, the permission stall on every dispatched call, the allow rules auto mode dropped, and which calls the engine routed to the classifier.
- `cli-health` [`min_calls`, `limit`]: Bash calls grouped by the program they run, with error rates that count SQL errors a zero exit hid, latency, retries, and the top error signatures.
- `delegation`: Whether expensive orchestrator sessions push work down to cheaper models on Agent/Task spawns.
- `field-drift` [`new_days`, `cutoff_date`, `min_rows`]: Fields the harness started or stopped writing, on record kinds the corpus carried before and since.
- `hook-block-then-retry-success` [`hook`, `within_seconds`]: Per hook, blocks that were retried away by a same-hook success in the same session within N seconds: noise rather than a genuine redirect.
- `hook-blocks` [`hook`]: Hook overfiring, blocking events grouped by hook and normalized reason signature, including the PreToolUse denies `hook_events` never records.
- `hooks` [`event`, `hook`]: Per-hook runs, friction rate, and latency corrected for host-wide slowdowns, one row per hook keyed by command (or `hook_name` when no command is recorded).
- `index-health` [`min_active_days`, `new_days`, `stale_days`, `deny_window_days`, `refresh_days`, `refresh_slow_ms`, `projects_glob`]: The index auditing itself. Run it first in any analysis pass, since its alerts cap what the rest can claim.
- `model-summary`: Assistant text item, message, session, and character counts per model.
- `mods`: Whether each mod was live and healthy: the sessions it started in, the events it emitted, how many failed, and where the sessions were reached from.
- `outcomes` [`ongoing_hours`]: Session terminal states (shipped, abandoned-with-edits, handed off, no artifact), the outcome side the activity queries never measure.
- `permissions` [`denial_kind`, `limit`]: Denied tool calls, one row per denial, with the mechanism that stopped it and the signal that answered.
- `plan-iterations` [`min_plans`]: One row per ExitPlanMode present, ordered within a session, measuring the append-only re-present signature.
- `plan-sizes` [`threshold`]: Weekly trend of plan sizes, the steering metric for the plan plugin's ExitPlanMode size gate.
- `repeat-read-waste`: Repeat Reads split by cause, isolating the true context tax from pagination and fan-out.
- `sandbox-bypass-effective-command` [`min_count`]: Bypassed commands by their real verb, ranked by frequency, with the split between bypasses that followed a failed sandboxed run (`justified`) and those that did not (`reflexive`): the `excludedCommands` candidates.
- `sandbox-bypass-scaffold`: Weekly share of `dangerouslyDisableSandbox` calls whose commands already escape through `excludedCommands`, the `sandbox` plugin's retirement signal.
- `sandbox-path-deny-recurrence`: `Operation not permitted` and adjacent Bash failures bucketed into concrete sandbox config gaps, with recurrence and date span.
- `search` [`query`, `limit`]: Find sessions by keyword, ranked by BM25 over each session's label, prompts, assistant prose, thinking, and tool calls with their output.
- `skill-activity`: Work attributed to each skill: assistant turns, sessions, and input, output, and cache tokens.
- `skill-auto-vs-explicit` [`min_calls`]: Per skill, how invocations split between the model choosing it (`model_auto`), another skill chaining into it (`chained`), and the user typing its slash command (`explicit`).
- `stats`: Tool usage breakdown with error rates and aggregate totals.
- `stop-hook-noop-detector`: Stop hooks that cost wall-clock and produce nothing, ranked as removal candidates.
- `text-export` [`role`, `model`, `min_chars`]: Dump cleaned prose from `text_content`, one row per text item, TSV-friendly.
- `tool-failure-rates` [`min_calls`, `limit`]: Per-tool failure rates over calls that ran, with the failures grouped by normalized signature and dated so a fixed failure reads as stopped.
- `top-sessions` [`sort`, `limit`]: Sessions ranked by spend, one row per session, carrying `msgs`, `out_tokens`, `avg_out`, `cost_usd_est`, and `last_activity`.
- `usage-spikes` [`bucket_minutes`, `limit`]: Ranked (session, time bucket) burn windows across the corpus, the same shape columns as `usage-timeline` plus `host`, `session_id`, and `repo` (the last path component).
- `usage-timeline` [`session` (required), `bucket_minutes`]: One session's token burn per time bucket, with estimated cost and a context-size proxy.

## On-Disk Queries

These read files rather than the index, each through a self-defaulting glob that `SET VARIABLE` overrides and `~` expands to home. The two marked with an extension load it with `-cmd ".read resources/extensions.sql"` after `-init resources/limits.sql`. For a new markdown or YAML need, feed the glob to `read_markdown_sections` or `read_yaml_frontmatter` rather than reinventing regex parsing, and never materialize file bodies into a column.

<!-- generated:on-disk-queries -->
- `hook-config-vs-observed` [`hook`, `hook_config_glob`]: Hooks configured on disk but never observed firing in the index, left-joined so the `observed_fires = 0` rows surface.
- `hook-self-timing` [`metrics_glob`, `hook`]: Hook latency from the hooks' own clocks, read off `~/.claude/hook-metrics/*.jsonl` rather than the index.
- `plan-sections` [`plans_glob`, `markdown` extension]: One row per markdown section across plan files on disk, joined to the session that produced each plan.
- `skill-config-vs-observed` [`skill`, `plugin_skill_glob`, `user_skill_glob`, `project_skill_glob`, `yaml` extension]: Installed skills that never fire, the curation instrument: SKILL.md frontmatter on disk left-joined against observed `skill_calls` and typed slash commands, zero-fire first.

## Tables and Views

Every table and view carries a `host` column (`local` for this machine, the label for imported ones). The `sessions` view adds `project_id` (`host || ':' || project_path`) for cross-host project identity.

- `raw`: one row per JSONL line, **every record type** (chat, attachments, system events, permission modes, titles, queue ops, snapshots, and more), not just user/assistant. Pinned scalar columns (`host`, `session_id`, `type`, `project_path`, `git_branch`, `is_meta`, `is_sidechain`, `duration_ms`, `timestamp`, `input_tokens`, `output_tokens`, the four `cache_*_tokens`, `uuid`, `message_id`, `model`, `entrypoint`, `attribution_skill`/`plugin`/`agent`, `title` for title records, `content_text` for string prompts, `source_file`, `source_line`) plus a `data JSON` column that holds the full original line. Filter and group on a pinned column rather than its `data` path: it skips parsing the JSON. Pinned numerics use `TRY_CAST`, so a divergent value type yields NULL rather than failing the import.
- `records`: universal union over `raw`, one row per line, with a normalized `kind` label (`type`, plus `subtype`/attachment kind when present) and the cross-cutting dimensions (`uuid`, `parent_uuid`, `permission_mode`, `version`, `slug`, `is_meta`, `is_sidechain`) every record may carry, plus full `data`. `SELECT kind, COUNT(*) FROM records GROUP BY kind` is the whole taxonomy. Reach into `data->>'$.path'` for anything not pinned. The `fields` view lists those paths.
- `attachments`: one row per `attachment` record (the richest non-chat category: hooks, diagnostics, skill/tool listings, plan/auto mode, queued commands, command permissions). Columns: `kind` (attachment subtype), `hook_name`, `hook_event`, `tool_use_id`, `is_sidechain` (the attachment landed in a subagent context, not the main thread), `attachment JSON` (full payload), `data`. **A `nested_memory` row's raw attachment length double-counts content**: `attachment->'$.content'` carries both `content` (the rendered, frontmatter-stripped body actually injected) and, one level deeper at `rawContent`, the full original file including frontmatter. The two are near-duplicates and together are ~85-95% of `length(attachment::VARCHAR)`, so measuring raw attachment length overstates injection cost roughly 2x. Measure `attachment->'$.content'->>'$.content'` instead. No shipped query is currently affected: `catalog-reinjection-thrash-sessions` is the only query summing raw attachment length, and it is scoped to `skill_listing`/`deferred_tools_delta`.
- `system_events`: one row per `system` record. `uuid`, `subtype`, `level`, `content`, `duration_ms`, `message_count`, and per-subtype fields: stop-hook (`hook_count`, `prevented_continuation`, `stop_reason`, `hook_infos JSON`), compaction (`compact_trigger`, `compact_pre_tokens`, `compact_duration_ms`), API errors (`error_code`, `retry_attempt`).
- `stop_hook_runs`: one row per Stop hook that fired, unnested from `system_events.hook_infos`. Columns: `tool_use_id` (the Stop, shared with every hook attachment it produced), `command`, `duration_ms`, `prompt_text` (set when the entry is a queued prompt the harness re-injected at Stop rather than a configured hook, NULL for real hooks). The harness's own roster, so unlike `hook_events` it includes a hook that produced no output. Replayed summary records are deduped by uuid.
- `hook_events`: one row per `hook_*` attachment (every event: PreToolUse, PostToolUse, Stop, SessionStart, UserPromptSubmit, PermissionRequest), with replayed lines deduped. `kind`, `hook_event`, `hook_name`, `command` (exact script, unwrapped from the payload for a `hook_blocking_error`), `exit_code`, `duration_ms`, `decision` (allow/ask/deny, parsed from the stdout JSON of a hook_success when the hook returns a permission decision), `reason`, `additional_context` (set on `hook_additional_context` rows only), `blocked` (boolean), plus `stdout`/`stderr`/`content`/`blocking_error`.
- `hook_blocks`: the friction surface, `hook_events` filtered to events that stopped or interrupted a tool call or the model. `decision` is deny/ask/block, `reason` is the surfaced message, `agent_id` names the blocked subagent (NULL on every row today, since the harness writes hook records only to the parent transcript). Find overfiring hooks here (high counts, repeated blocks within a session). Blind to PreToolUse denies: see `hook_denies`.
- `debug_events`: this machine's `~/.claude/debug/<session>.txt` lines that carry classifier timing, present only for sessions run with debug logging on. Rows outlive their files, which retention prunes oldest first past 2 GB. `event` is the `[Stall]` event name (`classifier_request_started`/`_finished`, `tool_dispatch_start`/`_end`) with its `key=value` pairs in `fields` JSON (`stage`, `outcome`, `durationMs`, `toolUseId`, `permissionDecisionMs`), or `dangerous_rule_ignored` with `fields.rule` and `fields.source` for an allow rule auto mode dropped. `session_id` is the file name without `.txt`. Read with the `classifier` query.
- `mod_events`: one row per event a mod emitted through the mod-events plugin, from `~/.claude/mod-events/<session>/<mod>.<instance>.<n>.jsonl`. Each line is an OTel log record. `event_name` is `<mod>.<event>` (`<mod>.session.start` is each mod's heartbeat), `ok` is false when `severity` is `WARN` or above, `duration_ms` is set when the mod measured one, `surface` is `local`, `mosh`, or `ssh` once the session's heartbeat has judged it, and `attributes` holds the mod's detail with `session.id` and `duration_ms`. Rows outlive their files, which retention prunes oldest first past 500 MB. Read with the `mods` query.
- `classifier_verdicts`: one row per tool call the `auto-mode` mod recorded, from its `tool.verdict` events in `mod_events`: the engine's `decision`, the deciding `rule`, `hook`, or `setting`, the `reason`, the `decider` an ask went to when it was not a dialog (`host`), the organization's `ceiling`, `read_only` when the tool ran the input read-only, `check_ms` to the verdict, `duration_ms` for the call, the `outcome`, and `interactive`, true for a tool that waits on the person (`AskUserQuestion`, the plan-mode tools), whose `duration_ms` is the person's time.
- `hook_denies`: PreToolUse denies recovered from the denied call's tool_result, which is the only trace a `permissionDecision: deny` leaves (no hook record is written). Columns: `hook_name` (a label from the pattern map, `(unmapped)` when none matches), `denied_tool`, `denied_command`, `reason`, `deny_source`, `tool_use_id`, `agent_id` (the subagent denied, NULL on the main thread). `session_id` names the transcript, which a subagent inherits from its parent. This is the one blocking channel subagents contribute to, so group per-session counts by `agent_id` too. `deny_source` is `field` (`permissionDecision`, 2026-10-07 on), `prefix` (the `PreToolUse:<Tool> hook error:` text, 2026-09-19 on), or `pattern` (the hand-kept map, the only signal earlier), so counts step at both dates. Rows already present in `hook_blocks` (a declined `ask`) are excluded, so the two views can be unioned without double-counting.
- `messages`: view over `raw` filtered to `type IN ('user', 'assistant')`, with a derived `content_text` (string-form messages only), `model`, token columns (`input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens`), attribution columns (`attribution_skill`, `attribution_plugin`, `attribution_agent`, `attribution_mcp_server`, `attribution_mcp_tool`), plus `prompt_source` (the harness's `$.promptSource`: `typed`, `system`, `queued`, `sdk`, `suggestion_accepted`, from 2026-06-03) and `interrupted_message_id` (the message a turn cut off, set on well under half of interrupted turns, so it identifies an interruption rather than counting them).
- `command_markers`: one row per typed slash command, the only trace a typed invocation leaves, since the harness emits no Skill tool_use for one and `skill_calls` never sees it. Columns: `command` (the name as typed, namespaced or bare), `session_id`, `timestamp`, `project_path`, `source_file`, `source_line`. Scoped to a user message that opens with the `<command-name>` block, so a transcript quoted in prose or dumped into a tool result is not counted, and replayed lines are deduped. Resolving `command` to a skill is the caller's job: a bare name reaches a personal or project skill, or a plugin's entry skill (`<p>:<p>`), and nothing else.
- `session_labels`: one row per labeled session, the display name the harness assigns. Columns: `label`, `label_source` (`custom-title` for a user rename, `ai-title` for the generated one, `agent-name` for a pinned agent). One row per session, preferring a custom title, then the AI title, then the agent name, and within a kind the latest record. Labeling replaced the `summary` records the index used to pin, which stopped being written.
- `message_usage`: one row per assistant message with deduped token columns (`input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens` as MAX per message id), the cache-write TTL split (`cache_1h_tokens`, `cache_5m_tokens`, both subsets of `cache_creation_tokens`, for cost weighting), plus `model`, attribution columns, `is_sidechain`, `source_file`, and `content_rows` (raw row count). **Sum tokens from here, not from `raw`/`messages`**: every content-block row repeats the parent message's usage, so per-row sums inflate totals 2-3.5x.
- `content_items`: one row per element of `data->'$.message.content'`, plus one `type = 'prompt'` row carrying a typed prompt (a string rather than a block array) in `text`. Pinned columns (`type`, `name`, `id`, `tool_use_id`, `text`, `content`, `is_error`, `tool_denial_kind`), the parent message's `role`, `model`, `is_meta` and attribution (`attribution_skill`/`plugin`/`agent`), plus `data JSON` (the content item) and `tool_use_result JSON` (merged from the parent message). Replayed lines from session rewind/resume are deduped within a session (by record uuid, then by tool id, keeping the main-thread copy), so tool_use/tool_result counts are one row per event.
- `fields`: the field registry, one row per `(host, type, path)` with `first_ts`, `last_ts`, `first_version`, `last_version` (the harness `version` on the first and last line), and `n` lines. Paths stop at `$.key.child`, plus `$.message.usage.<key>`, and a map keyed by ids collapses to `$.key.*`. Drill deeper with `json_keys(data, '$.path')` over `records`. `field_drift(since, host)` returns the `new` and `dead` paths around a cutoff, `field_triage` holds the judged paths it skips, and `view_paths` the paths the views read.
- `diagnostics`: one row per type-checker/linter/LSP diagnostic surfaced in-session. Columns: `file`, `severity`, `source`, `code`, `message`. Unnested from `diagnostics` attachments.
- `file_operations`: one row per `Read`/`Write`/`Edit`/`MultiEdit`/`NotebookEdit`, with `operation`, `file_path`, attribution, and `agent_id`. What you work on, and under which skill/plugin/agent.
- `pr_links`: pull requests opened from a session, one row per distinct link (the harness re-emits the record across turns; the view dedupes and keeps the first emission's timestamp). Columns: `pr_number`, `repository`, `url`, `session_id`. Join to `sessions` to connect work to shipped outcomes.
- `text_content`: one row per prose `text` or `prompt` item in `content_items` across user and assistant messages, excluding meta messages. Columns: `session_id`, `timestamp`, `role`, `model` (NULL for user), `project_path`, `text` (fenced and inline-backtick code stripped), `raw_text`, `source_file`, `source_line`.
- `sessions`: aggregated session-level stats (start/end time, duration, message counts), `entrypoint` (the earliest `$.entrypoint` its messages carry: `cli`, `claude-desktop`, `remote_desktop`, and so on, NULL before the field existed), plus the session's `label` and `label_source` from `session_labels`.
- `tool_calls`: one row per tool use, with `file_path` and `command` (from the tool input), attribution (`attribution_skill`/`plugin`/`agent`), and `agent_id`. `session_id` is the transcript's, which a subagent inherits from its parent, so any per-session count needs `agent_id` alongside it.
- `tool_errors`: tool results where `is_error` is true, joined with the originating tool call. `denial_kind` names the mechanism that stopped the call (`user-rejected`, `permission-rule`, `automode-blocked`, `automode-unavailable`) and is NULL for an ordinary failure. `error_type` stays the coarse `rejection`/`failure` split, where `rejection` means a user rejection specifically, so a `permission-rule` deny still reads as a `failure`. `agent_id` comes from the error row and names the subagent that hit it.
- `permission_requests`: one row per denied tool call, every mechanism, plus each prompt the user approved since 2026-10-07 (NULL `denial_kind`). `decision`, `decision_source`, and `reason_type` come from `$.permissionDecision`, NULL before that date. `denial_kind` is what stopped it, `kind_source` is which signal answered (`field` from `$.toolDenialKind`, or `result-string` from the harness's fixed rejection text before that field shipped on 2026-07-02), and `agent_id` names the subagent denied.
- `sandbox_bypasses`: Bash calls that used `dangerouslyDisableSandbox=true`, with back-links to retried failures. The back-link requires the same `agent_id`, so sibling subagents sharing a session id cannot be paired into a retry that never happened.
- `skill_calls`: one row per `Skill` tool invocation. It misses typed slash commands (`command_markers`) and every load that never went through the tool (`skill_loads`).
- `skill_loads`: one row per skill body that entered context, whichever path put it there. Answers whether a session actually ran a skill's instructions and which revision. Columns: `skill` (namespaced for a plugin skill), `plugin`, `plugin_version` (the plugin cache directory's version, a 12-character commit prefix for a git marketplace such as `bendrucker`, NULL for a personal, project, or `--plugin-dir` skill), `trigger` (`tool` for the Skill tool, `harness` for a typed command or an agent's preloaded skill, `compaction` for the re-injection after a compaction), `tool_use_id` (joins `skill_calls.tool_id` when `trigger = 'tool'`), `dir`, `agent_id`, `session_id`, `project_path`, `timestamp`, `source_file`, `source_line`. A Skill call with no `tool` load failed, ran forked, loaded a bundled skill (whose body doesn't name a directory), or re-invoked a skill already in context, which the harness answers with a stub instead of the body.
- `plan_calls`: one row per `ExitPlanMode` tool use. Columns: `tool_use_id`, `plan_file`, `plan_chars` (length of plan text; fetch the full text via `json_extract_string(data, '$.input.plan')` from `content_items` when needed), `outcome` (`approved` / `denied` / `redirected` / `handoff` / `unknown`), `plan_seq` (1-based ordinal within the session). `handoff` is a rejection of the session's last plan with no file edits after it: the deliberate reject-and-implement-elsewhere workflow. `redirected` is any other rejection (mid-session churn). `denied` is a present a PreToolUse hook refused.
- `plan_sessions`: one row per session that used plan mode. Columns: `plan_count`, `redirect_count`, `approved_count`, `handoff_count`, `denied_count`, `unknown_count`, `first_plan_ts`, `last_plan_ts`.

## Macros

- `date_filter(ts, after, before)`: filter a timestamp column by optional date bounds.
- `project_filter(path, pattern)`: match the last path component against a glob pattern.
- `host_filter(host_col, host_val)`: pass through when `host_val` is NULL, else match the host column.
- `project_id(host, path)`: `host || ':' || path`, a cross-host project identity.
- `subagent_id(source_file)`: the subagent that produced a row, NULL on the main thread, so `(host, session_id, agent_id)` is the per-context key. `03_macros.sql` records why the transcript path beats `is_sidechain` and `attributionAgent`.
- `denial_kind(kind, tool_use_result)` / `denial_kind_source(kind, tool_use_result)`: why a tool call was denied, or NULL when the result is an ordinary failure, plus which signal answered. `$.toolDenialKind` states it outright but starts 2026-07-02; before that the only trace is the harness's fixed rejection string, which covers user rejections alone. A count spanning that boundary reads as coverage rather than as a change in behavior when it is split by source.
- `model_input_rate(model)` / `model_output_rate(model)`: estimated per-MTok USD input/output rate for a model name (matched with ILIKE, so it works on full model ids): fable/mythos 10/50, opus 5/25, sonnet 3/15, haiku 1/5, else 5/25. The shared rate table for the cost-estimate queries, a snapshot of published API rates as of 2026-07-24. Rates are keyed by family, so a family arm can drift from a specific model's current rate.
- `model_family(model)`: collapses a concrete model id or a short `model` override (e.g. `opus`) to a family label (`fable`, `opus`, `sonnet`, `haiku`, `other`, or `NULL` for a `NULL` input) with the same ILIKE patterns as the rate macros. Used by `delegation` to bucket parent and spawn models onto one axis.
