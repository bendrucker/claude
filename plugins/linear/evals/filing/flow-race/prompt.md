File a Linear issue on ENG for this race. When Stripe sends a webhook, the API writes an event row and enqueues a job. The billing worker picks the job up and marks the invoice paid. Separately, the reconciler runs every 5 minutes, reads unpaid invoices, and re-fetches them from Stripe. If the reconciler reads the invoice after the event row is written but before the worker commits, it writes the stale "open" status back over "paid". We've seen it 3 times this week. It's related to ENG-330.
