Read only the issue between the <issue> lines, above any "Agent Context" heading. Requirements say what must be true when the work is done. Acceptance criteria verify it: each criterion names a concrete check an agent or reviewer can run (an action or input, and the result to observe), so someone can tell whether the work is finished. Test each criterion against the requirements: if deleting it loses nothing the requirements do not already say, it restates them and fails. A criterion that rewords a requirement ("Pinning moves it to the top group" under "Pinned items render above unpinned ones") fails, and so does one with no observable result, such as a pointer to a test suite or a local environment with nothing to observe. The issue fails when any criterion fails. An issue with no acceptance criteria passes. For example, the requirement "Exports respect the current filters" pairs with the criterion "Filter the report to one region, export, and the CSV holds only that region's rows".
