File an issue on TakeScoop/kubectl-exec-forward: `--context` doesn't propagate to the pod lookup. Repro: kubeconfig's current context is `a`, pass `--context b`. The pod gets found in `a`, but the forward connects with `b`. Usually fine since both contexts share objects, but a Deployment/ReplicaSet's pod name is randomized per context, so looking it up under `service/my-svc` finds a pod in `a` that doesn't exist in `b`: `Error: error upgrading connection: pods "my-app-abc123" not found`. Workaround for now: switch the current context first (`kubectl config use-context` or `kubectx`).
