# `evals:hill-climb` Eval

A native `claude plugin eval` suite for the judgment steps of `evals:hill-climb`: the Decide step, with the Stall and Stopping rules and the version re-baseline, and the Error Analysis buckets. Every case hands the session `/evals:hill-climb <target> <suite>` with frozen inputs. Nothing builds or runs, so a case costs one read-and-write session instead of a climb. Cases are tagged by family (`decide`, `bucket`) and by split (`dev`, `holdout`). Decide cases carry a third tag for the harness that rendered their evidence. The suite is `.local-only`, since a labeled-PR run of all 41 cases would pass the monthly eval budget. Dispatch it with `--tag dev` or `--tag holdout`.

## Decide

33 single-turn cases, generated by [`scripts/gen-decide.ts`](scripts/gen-decide.ts) from [`truth.json`](truth.json). Each hands the session a `CLIMB.md` excerpt (base SHA, `claude --version` and model per column, the history, the hypothesis, the pre-registered target and guard graders, the run counts), then the frozen comparison output for the dev runs and, where the trap needs it, for the holdout pair. The reply ends with a `Decision:` line, one of `accept`, `reject`, `more-runs`, `stall`, `stop`, or `re-baseline`.

Each trap appears on three of the four target types (`skill`, `agent`, `rule`, `prompt`), skipping a different type per trap. The third appearance in generation order is the holdout. The targets are invented (a `release-notes` skill, an `invoice-checker` agent, a `log-fields` rule, a `support-bot` prompt) and so are their cases and graders.

| Trap | Expected | What's planted |
| --- | --- | --- |
| `control-star` | `more-runs` | a with-arm target star matched by an equal star on the without (control) arm |
| `underpowered` | `more-runs` | the only gain sits on cells with fewer than 4 runs a side (`†`) |
| `off-target` | `reject` | the only star is on a grader outside the pre-registered targets |
| `guard-drop` | `reject` | the target starred up and a pre-registered guard starred down |
| `holdout-fell` | `reject` | a dev target star, and a final holdout score below the base |
| `quota-void` | `more-runs` | candidate runs errored on a session limit (`!` rows) |
| `second-null` | `stall` | the previous candidate was null and this one is null too |
| `saturated` | `stop` | noise runs put dev at 1.00 on both arms, so the candidate cannot rise |
| `efficiency-unregistered` | `reject` | pass counts flat, seconds and cost starred better, efficiency not a target |
| `version-drift` | `re-baseline` | `claude --version` or the model differs between the baseline and the candidate column |
| `clean-accept` | `accept` | balance case: target starred up, guards and control flat, holdout holds |

#### Harnesses

The same evidence is rendered once per harness in [`scripts/renderers/`](scripts/renderers/), rotating across a trap's three appearances so each harness shows up in both splits:

- `native` is the `compare.ts --markdown` report: starred rows first, then the collapsed tables, with `*`, `†`, and `!` marks. The generator builds it with the real `render` from `packages/evals`, so the format follows the tool.
- `csv` lists `case,arm,grader,runs,passes` for each column, then a separate table of p-values. It has no stars.

The p-values in every harness come from the same permutation test, so a case reads the same whichever harness drew it. `neutral` runs on every case but the `native` ones. It fails a reply that sends the reader to `run.ts`, `regrade.ts`, `calls.ts`, or `compare.ts` without `--adapter`, none of which can read those columns.

#### Graders

- `decision` matches the reply's last `Decision:` line against the expected verdict.
- `reason` passes when that decision is right and the reply names the trap's cause in any of several wordings, so a case scores on the call first.
- `neutral` as above.

Edit `truth.json` or the generator and rerun `bun plugins/evals/evals/hill-climb/scripts/gen-decide.ts` rather than editing a case. A test fails when the committed cases drift from it, and another asserts which rows of each trap star.

## Bucket

Eight hand-written cases, two per Error Analysis bucket, four of them `holdout`. Each gives a failing grader's explanation and a short trace excerpt from a climb and asks which bucket the failure belongs to. The reply ends with a `Bucket:` line.

| Case | Split | Bucket | What's planted |
| --- | --- | --- | --- |
| `bucket-skill-lead-line` | dev | `skill` | the skill fired and the reply breaks a length rule it states |
| `bucket-skill-hedged-limit` | holdout | `skill` | the session opened the rule in a reference and still hedged it |
| `bucket-grader-key-order` | dev | `grader` | an `Edit` call meets the intent and an anchored trace regex misses the key order |
| `bucket-grader-negated` | holdout | `grader` | a `not_contains` regex fails a reply that rules the cache out |
| `bucket-reach-no-skill-call` | dev | `reach` | no `Skill` call, indicator at 0/6, the reply is the model default |
| `bucket-reach-description-miss` | holdout | `reach` | the request never uses the words in the skill description, so the skill stays quiet |
| `bucket-floor-missing-input` | dev | `floor` | the task needs a ticket the fixture never provides, and the stronger-model run fails too |
| `bucket-floor-hard-digest` | holdout | `floor` | an MD5 digest by hand with no tool, and the tier above fails too |

[`scripts/gen-bucket.ts`](scripts/gen-bucket.ts) writes each case's `case.yaml` and graders. The `prompt.md` files are hand-written.

## Running

`bun evals/native/run.ts plugins/evals/evals/hill-climb --ref <ref> -- --tag dev --runs <n>` runs the plugin at `<ref>` against a no-plugin baseline on the dev split, with the Bash sandbox disabled. Add `--tag holdout` to confirm a win, `--tag bucket` or `--tag decide` for one family, and `--model <id>` to override the model. Results land in the gitignored `results/<timestamp>-<label>/`.

- `bun evals/native/compare.ts <base>/aggregate-result.json <candidate>/aggregate-result.json --suite plugins/evals/evals/hill-climb` compares the native scores by case and tag.
- `bun evals/native/check.ts plugins/evals/evals/hill-climb` tests the regex graders against [`examples/`](examples/): a passing reply for every trap and bucket case, and failing replies per grader for `decide-control-star-agent` (native) and `decide-control-star-rule` (csv).
- `bun test plugins/evals/evals/hill-climb` covers the generators, the planted stars, the harness renderings, and the graders.
